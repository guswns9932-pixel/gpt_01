# WriteNoble — 웹소설 집필 엔진 스킬

> 이 스킬은 **작품 내용이 아니라 작업 방식**을 담는다.
> 작품별 설정(세계관/인물/줄거리)은 각 작품 폴더의 `STORY_MEMORY.md`에 저장하고,
> 이 스킬은 어떤 작품에도 동일하게 적용되는 절차·문체 규칙·저장 규칙을 정의한다.

---

## 1. 프로젝트 구조 규칙 (다작품 지원)

이 스킬은 한 저장소 안에서 여러 작품을 동시에 관리할 수 있도록 설계한다.

### 1-1) 작품이 1개뿐인 경우
```
STORY_MEMORY.md          ← 이 작품의 장기 메모리
EPISODE_TEMPLATE.md      ← 회차 작성 템플릿
episodes/
  EP_001.md
  EP_002.md
  ...
```

### 1-2) 작품이 2개 이상인 경우 (신작 시작 시 전환)
```
works/
  <작품슬러그1>/
    STORY_MEMORY.md
    EPISODE_TEMPLATE.md
    episodes/EP_001.md ...
  <작품슬러그2>/
    STORY_MEMORY.md
    EPISODE_TEMPLATE.md
    episodes/EP_001.md ...
```
- 슬러그는 영문 소문자+하이픈 (예: `sight-sense`, `moonlit-heir`)
- 기존에 루트에 작품이 하나 있었다면, 새 작품 시작 시점에 그 작품도 `works/<기존슬러그>/`로 옮길지 사용자에게 물어본다 (임의로 이동 금지 — 반드시 확인 후 진행)

### 1-3) 작품 판별 규칙
- 작업 요청에 작품명이 명시되면 해당 작품 폴더 사용
- 명시되지 않고 작품이 1개뿐이면 그 작품으로 자동 진행
- 명시되지 않고 작품이 2개 이상이면 **반드시 사용자에게 작품을 먼저 확인**

---

## 2. 신작 시작 절차

새 작품을 시작할 때는 아래 순서를 따른다.

1. 작품 폴더 위치 결정 (1-1/1-2 규칙에 따라)
2. `STORY_MEMORY.md` 생성 — 아래 "3. STORY_MEMORY 표준 목차"를 뼈대로 사용
3. `EPISODE_TEMPLATE.md` 생성 (기존 템플릿 재사용 가능, 작품 무관 범용 양식)
4. `episodes/` 폴더 생성
5. 코어 설정이 비어 있으면 **"8. 미확정 항목 처리 규칙"**에 따라 사용자에게 확인

## 3. STORY_MEMORY 표준 목차 (모든 작품 공통 뼈대)

새 작품의 `STORY_MEMORY.md`를 만들 때 아래 섹션 구조를 기본으로 사용한다.
장르나 작품 성격에 따라 불필요한 섹션은 생략하거나 이름을 바꿀 수 있다.

1. 작품 코어 (장르, 키워드, 톤, 시점)
2. 세계관 (배경, 핵심 설정, 독자 설득 근거)
3. 주인공 능력/핵심 컨셉 (능력물이 아니면 생략 가능)
4. 인물 설계 (주인공/조력자/라이벌/빌런 카드)
5. 집필 규칙 메모 (이 작품만의 예외 규칙이 있다면)
6. 결말 설계 (엔딩 방향, 카타르시스 포인트)
7. 능력/설정 성장 단계 & 핵심 에피소드 (해당되는 경우)
8. 시즌/전체 아크 배치
9. 로맨스/개그 완급조절 배치
10. 집필 전 미확정 항목 체크리스트
11. 변경 이력 (버전별 설정 변경 기록)

> 이 목차는 뼈대일 뿐이다. 실제 내용(세계관 설정, 캐릭터 이름 등)은
> 절대 이 스킬 파일에 넣지 않는다 — 반드시 해당 작품의 STORY_MEMORY.md에 기록한다.

---

## 4. 집필 강령 (문체 원칙 — 장르/작품 공통)

### 4-1) 시점
- 기본값: 1인칭 (주인공 시점 고정), 대본식 지문 서술 금지
- 작품별로 3인칭 등 다른 시점을 쓰기로 확정했다면 STORY_MEMORY.md에 명시하고 그것을 우선

### 4-2) 문체 원칙
1. 문단 길이: 1~3문장 유지, 장문 설명 지양
2. 대사:행동:정보 비율 = 4:4:2 권장
3. 사건 진입: 회차 첫 20% 안에 사건 또는 위협 등장
4. 엔딩 훅: 매 회차 마지막 3~5문장에 반전/선택/위험 중 1개 이상 배치
5. 설명이 대사·행동보다 길어져 속도감이 죽지 않도록 주의

### 4-3) 분량/정보량 가이드
- 기본 분량: 1,800~2,500자 (초반부), 주요 이벤트 회차 2,500~3,200자
- 신규 설정: 회차당 1~2개 이내
- 신규 고유명사: 회차당 최대 3개
- 인물 감정 축: 회차당 1개에 집중

### 4-4) 금지 사항
- 대본/시나리오식 지문 서술 (예: "장소: OO", "시간: OO" 형태로 본문 나열)
- 인물 말투가 서로 비슷해져 구분이 안 되는 상태
- 미확정 설정을 숨기거나 임의로 지어내고 본문 집필을 진행하는 것
- 직전 회차 인수인계 메모와 충돌하는 설정을 그대로 쓰는 것

---

## 5. 회차 작성 절차 (고정 순서 — 모든 작품 공통)

```
1. 대상 작품 확인 (1-3 규칙)
2. 해당 작품의 STORY_MEMORY.md 확인
3. 직전 회차 파일의 "다음 화 인수인계 메모" 확인
4. 새 파일 생성: episodes/EP_###.md (해당 작품의 EPISODE_TEMPLATE.md 기반)
5. 본문 작성 (4. 집필 강령 준수)
6. 인수인계 메모 작성 (5-1 항목 전부)
7. 자가 점검 체크리스트 완료 (5-2)
8. 설정이 바뀌었다면 STORY_MEMORY.md 변경 이력에 기록
9. git add → git commit → git push
```

### 5-1) 인수인계 메모 필수 항목
- 이번 화 핵심 사건 3줄
- 상태 변화 (주인공 / 조력자 / 라이벌 / 빌런·세력)
- 특수 능력·설정 사용 로그 (해당되는 경우: 단계 / 횟수 / 대가·후유증)
- 떡밥/복선 현황 (신규 / 회수 / 미회수 TOP3)
- 다음 화 즉시 시작 문장 (1~2문장)
- 다음 화 목표 / 실패 시 대가
- 검색용 키워드 8개

### 5-2) 자가 점검 체크리스트
- [ ] 첫 20% 안에 사건/위협이 등장한다
- [ ] 문단이 1~3문장 중심으로 유지된다
- [ ] 인물별 말투가 서로 구분된다
- [ ] 마지막 3~5문장에 훅이 있다
- [ ] 직전 화 인수인계 메모와 설정 충돌이 없다

---

## 6. 연속성 보존 규칙

- 새 아이디어가 기존 설정과 충돌하면, 먼저 해당 작품의 STORY_MEMORY.md 기존 항목을 기준으로 조정
- 설정을 변경하기로 확정했다면 STORY_MEMORY.md "변경 이력" 섹션에 버전(v1.0, v1.1 ...) 형태로 반드시 기록
- 각 설정 항목은 항상 "확정 / 보류 / 폐기" 상태를 명시

---

## 7. 회차 작성 직후 자가 검토 루틴

1. 소리 내어 읽듯 처음부터 끝까지 낭독 점검 (어색한 문장 즉시 수정)
2. 첫 문단 / 끝 문단만 따로 읽고 훅 강도 점검
3. 불필요한 설명 10~15% 삭제
4. 직전 회차 인수인계 메모와 충돌 여부 재확인
5. 수정 완료 후 STORY_MEMORY.md·키워드 갱신 필요 여부 확인

---

## 8. 미확정 항목 처리 규칙 (필수)

작품 설정 중 미확정 항목이 하나라도 있는 상태에서 집필을 진행해야 하면,
**절대 임의로 지어내지 말고** 아래 형식으로 반드시 먼저 사용자에게 제시한다.

```
[미확정 항목]
- 항목명: ...

[추천안] (해당 장르 상위권 트렌드 기준 1~2개)
- A안: ...
- B안: ...

[선택하면 즉시 집필 가능한 최소 입력]
- ...
```

- 금지: 미확정 항목을 숨기거나 생략한 채 본문 집필을 진행하는 것
- 사용자가 값을 입력하면 그 값을 STORY_MEMORY.md의 "고정값"으로 간주하고,
  이후 변경 시에만 변경 이력에 새 버전으로 기록한다

---

## 9. Git 저장 규칙

- 작업 대상 브랜치는 세션/저장소 설정을 따른다 (현재 활성 브랜치 확인 후 그 브랜치에 커밋)
- 회차/설정 파일을 수정했다면 **커밋 후 반드시 push까지 완료**하는 것을 기본 동작으로 한다
- 커밋 메시지 형식:
  ```
  [동사] <작품/파일 식별자>: 한 줄 요약

  - 변경 내용 불릿 1
  - 변경 내용 불릿 2
  ```
- 설정(STORY_MEMORY.md) 변경과 본문(episodes/EP_###.md) 변경은 같은 작업 단위라면 함께 커밋 가능
- push 실패 시: 원인을 파악해 재시도하거나(네트워크 오류) 대체 경로(예: 플랫폼 API)를 시도하고, 사용자에게 상태를 명확히 보고한다

---

## 10. 이 스킬 사용 시 항상 지킬 것

1. 이 파일에는 특정 작품의 설정(세계관/인물/줄거리)을 절대 적지 않는다 — 오직 절차와 규칙만
2. 여러 작품을 오갈 때는 항상 "지금 어느 작품 작업 중인지"를 먼저 확실히 한다
3. 매 회차 작업은 5장의 고정 순서를 그대로 따른다
4. 설정 충돌·미확정 항목은 반드시 사용자에게 먼저 확인한다
5. 파일 변경 후에는 반드시 Git에 반영(add·commit·push)한다
